## URL設計（画面のパス）

| 画面 | パス | 認証 |
|------|------|------|
| S-01 ログイン | `/login` | 不要 |
| S-04 サインアップ | `/signup` | 不要 |
| S-02 タイムライン | `/timeline` | 必要 |
| S-03 投稿詳細 | `/posts/:id` | 必要 |
| S-05 プロフィール | `/users/:username` | 必要 |
| S-08 プロフィール編集 | `/profile/edit` | 必要 |

> **プロフィールのパスに id ではなく @ユーザー名 を使う理由:** URLを見ただけで誰のページか分かり、
> 共有もしやすいため（X/Twitter と同じ考え方）。`username` にはユニーク制約があるので一意に特定できる。
> 副作用として、**@ユーザー名を変更すると旧URLは404になる**（Xと同じ挙動として許容している）。

> **編集画面のパスに `:username` を入れない理由:** 編集対象がその `username` 自身であるため。
> `/users/:username/edit` にすると、保存した瞬間にURLが古い名前を指す状態になってしまう。

## 4. ワイヤーフレーム

### WF-01: ログイン画面（S-01）

```
+--------------------------------------------------+
|                                                  |
|                  RaiseTimeLine                   |
|                                                  |
|   +------------------------------------------+   |

|   +------------------------------------------+   |

|   +------------------------------------------+   |

|     パスワードが正しくありません）                |

```

### WF-02: タイムライン画面（S-02）

```
+--------------------------------------------------+
|  RaiseTL                  [🔍] [👤] [ログアウト]  |
+--------------------------------------------------+
|  [全体] [フォロー中(無効)]        [＋投稿する]     |
+--------------------------------------------------+
|            [ ↑ 5件の新着を表示 ]                 |  ← ポーリングで検知時のみ表示
|                                                  |
|  +--------------------------------------------+  |
|  | 鈴木さん ・ 5分前            [編集] [削除]   |  ← 自分の投稿のみ表示
|  | 今日はSpring Securityの講義。JWTむずかしい…  |  |
|  |                                            |  |
|  | 💬 3    ♡ 12                               |  |
|  +--------------------------------------------+  |
|  +--------------------------------------------+  |
|  | 高橋さん ・ 1時間前                          |  ← 他人の投稿は編集・削除ボタンなし
|  | 週末に撮った写真です                         |  |
|  | +----------------------------------------+ |  |
|  | |               （画像）                  | |  |
|  | +----------------------------------------+ |  |
|  | 💬 1    ❤ 8   ←（いいね済みは塗りつぶし）    |  |
|  +--------------------------------------------+  |
|                                                  |
|         （スクロールで自動的に次ページを読み込み） |
+--------------------------------------------------+
```

「＋投稿する」ボタンを押すとWF-02aの投稿作成モーダルが開く。タブは「全体」のみ機能し、「フォロー中」はPhase 3まで無効化（クリック不可）。検索・プロフィールボタンは配置のみで、遷移先の画面が実装されるまでは押しても反応しない。

**新着投稿の確認の流れ:** 画面を開いたまま30秒ごとに新着投稿の有無をバックグラウンドで確認する →
新着があれば画面上部にバナーを表示する → バナーを押すと最新投稿を取得しタイムライン先頭に反映する。
自動で差し込んだり、スクロール位置をずらしたりはしない（詳細は [docs/features/timeline-sync.md](./features/timeline-sync.md) を参照）。

### WF-02a: 投稿作成モーダル

```
+--------------------------------------------------+
|  投稿する                                    [×]  |
|  +--------------------------------------------+  |
|  | いまどうしてる？                            |  |
|  |                                            |  |
|  +--------------------------------------------+  |
|  [📷 画像を選択]                140/280  [投稿する]|
+--------------------------------------------------+
```

「＋投稿する」ボタンで開くモーダル。「📷 画像を選択」でファイル選択ダイアログを開く →
クライアント側でJPEG/PNG・5MB以内かを検証（違反時は選択欄の下にエラーメッセージ）→
問題なければ選択画像のプレビューをモーダル内に表示（「画像を削除」で選び直せる）→
投稿ボタン押下でサーバーに送信し、サーバー側でも同じ条件を再検証する →
成功するとモーダルが閉じ、タイムライン先頭に反映される。×ボタンでキャンセルできる。

## 5. デザイン方針

### カラーパレット

| 用途 | 色 | 補足 |
|------|----|----|
| ベース | 白（#FFFFFF）/ ごく薄いグレー（#F7F9F9） | X のライトテーマを参考にした清潔感のある背景 |
| テキスト | ダークグレー（#0F1419） | 真っ黒より目に優しい |
| アクセント | ブルー（#1D9BF0 系） | ボタン・リンク・アクティブ状態 |
| いいね | ピンク／レッド（#F91880 系） | いいね済み状態の表現 |

### UIコンポーネント方針

- Tailwind CSS をベースにユーティリティクラスでスタイリングする
- タイムラインは**中央1カラム（最大幅 600px 程度）**のカード型リストとする（X と同じ読みやすいレイアウト）
- いいね・コメントのアイコンは投稿カードの下部に横並びで配置し、数を隣に表示する
- ローディング中・エラー時の状態表示を必ず用意する（真っ白な画面にしない）
- 文字数カウンター（残り文字数）を投稿フォームに表示する
