# サーバー起動・ポート管理スキル

RaiseTimeLine プロジェクト（Spring Boot + Vite/React + PostgreSQL on Docker）のサーバー起動手順。

> **注意:** backend / frontend / docker-compose.yml は環境構築フェーズで作成される。
> 環境構築が終わるまで、このスキルの起動手順は実行できない（TaskManagement からの転用。構成は同一の前提）。

## 使用ポート（変更禁止）

| サーバー | ポート |
|---|---|
| バックエンド（Spring Boot） | **8080** |
| フロントエンド（Vite） | **5173** |
| データベース（PostgreSQL） | **5432** |

ポートを変えてはいけない理由：Vite のプロキシ設定と CORS 設定がこれらのポートを前提にしているため、別ポートで起動しても正常に連携できない。

## セッション開始時のヘルスチェック（実装作業の前に必ず行う）

**エラーが出てから調べるのではなく、作業を始める前に環境を揃える。**
2026-08-27 に決定。バックエンドの起動忘れによる「通信中にエラーが発生しました」が繰り返し発生していたため。

実装・画面確認を伴うセッションでは、本題に入る前に3つを確認し、落ちているものがあれば起動してから始める。

```bash
netstat -ano | findstr :8080   # バックエンド（Spring Boot）
netstat -ano | findstr :5173   # フロントエンド（Vite）
docker compose ps              # DB。5432 は Docker Desktop 経由だと netstat に出ないことがあるため、こちらで見る
```

- **8080 が空 → バックエンドが落ちている。** `backend/gradlew -p backend bootRun` で起動する
- **LISTENING だけを見て「起動成功」と判定しない。** 古い `java.exe` が居座っている場合があるため、
  アプリのログに `Started RaiseTimeLineApplication` が出たことで判定する
- 起動をバックグラウンドで行う場合は、ログをファイルへリダイレクトして上記の行を待つ

### 症状から原因を切り分ける

画面やブラウザの DevTools（F12 → Network タブ）での見え方で、原因はほぼ確定できる。

| 見え方 | 原因 | 見る場所 |
|---|---|---|
| `ERR_CONNECTION_REFUSED` / 「通信中にエラーが発生しました」 | **サーバーが起動していない。**アプリのバグではない | ポート・起動ログ |
| 500 | サーバーは生きている。アプリ内部のバグ | バックエンドのログ |
| 401 / 403 | 認証・権限の問題 | トークン・ログイン状態 |
| 404 | URL が違う | パスの綴り |
| ずっと「読み込み中」 | 応答が返らない（DB待ち・無限ループ） | DB接続・クエリ |

> **フロント（5173）だけ生きている状態に注意。** ログイン画面は表示されるので一見動いて見えるが、
> API は一切通らない。**「画面が出た＝環境が揃っている」ではない。**

> **将来対応（デプロイフェーズ）:** Spring Boot Actuator を導入し `/actuator/health` で生死を判定する。
> ALB のヘルスチェック先が必要になるため。開発中の起動確認が目的ではないので、今の段階では入れない。

## 起動前：ポート競合の確認と解消

起動前に必ず確認する。競合プロセスがあれば、停止してから起動する。別ポートへの切り替えや設定ファイルの書き換えは行わない。

```powershell
# 使用状況の確認
netstat -ano | findstr :8080
netstat -ano | findstr :5173
netstat -ano | findstr :5432

# 競合プロセスの停止（PIDを確認してから実行）
taskkill /PID <PID> /F
```

## 起動パターン

### 全サービス起動（通常の開発作業）

```powershell
# Step 1: データベース
docker-compose up -d

# Step 2: バックエンド（ポート8080）
cd backend
.\gradlew bootRun

# Step 3: フロントエンド（別ターミナル、ポート5173）
cd frontend
npm run dev
```

### フロントエンドのみ起動（UIのレイアウト・デザイン確認）

タイムライン取得など API に依存する機能はバックエンドなしでは動作しない。見た目の確認だけであればフロントのみで進められる。

```powershell
# ポート確認
netstat -ano | findstr :5173

# 起動（ポート5173固定）
cd frontend
npm run dev
```

## 禁止事項

- `8081`, `5174` など別ポートでの代替起動
- ポートを変えるための設定ファイル書き換え
- ポート競合を確認せずにそのまま起動を試みること
